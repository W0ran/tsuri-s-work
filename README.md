# AI Expert — автотесты (Python + Playwright + pytest)

## Стенды

| Окружение     | URL                                          |
|---------------|-----------------------------------------------|
| Тестовый      | https://dev-ai-expert.digitalplatform.kz      |
| Боевой        | https://ai-expert.digitalplatform.kz          |

Тесты по умолчанию работают против тестового стенда (`BASE_URL` в `.env`).

## Карта ролей

| Роль                  | Логин         | Доступ после входа                     | Статус покрытия          |
|-----------------------|---------------|------------------------------------------|---------------------------|
| Заявитель             | applicant     | `/wizard` (подача заявки)                | ✅ покрыт                 |
| Эксперт               | expert        | `/expert` (кабинет) + `/reference`       | ⏳ UI не изучен            |
| Администратор         | admin         | всё, включая `/admin`                    | ⏳ UI не изучен            |
| Председатель совета   | predsedatel   | —                                         | ⏳ UI не изучен            |
| Член совета           | sovet-tsuri   | —                                         | ⏳ UI не изучен            |

Пароли — только в `.env` (не в git, не в этом файле).

## Установка

```powershell
pip install -r requirements.txt
python -m playwright install
```

## Запуск тестов

```powershell
python -m pytest tests/ -v --headed
```

Только определённая роль:
```powershell
python -m pytest -m applicant -v
```

Всё, кроме security:
```powershell
python -m pytest -m "not security" -v
```

Быстро, без браузера в видимом режиме (headless, для CI):
```powershell
python -m pytest tests/
```

## Структура проекта

```
pages/
  common/        — общее для всех ролей (логин, рамка сайта: тема/язык/выход)
  applicant/      — заявитель: мастер заявки, загрузка документов
  expert/         — эксперт (заглушки, UI не изучен)
  admin/          — администратор (заглушки, UI не изучен)
  predsedatel/    — председатель совета (заглушки, UI не изучен)
  sovet_tsuri/    — член совета (заглушки, UI не изучен)

tests/
  common/         — логин, логаут, смена темы/языка — для всех ролей
  applicant/      — тесты заявителя (рабочие)
  expert/         — тесты эксперта (заглушки)
  admin/          — тесты администратора (заглушки)
  predsedatel/    — тесты председателя (заглушки)
  sovet_tsuri/    — тесты члена совета (заглушки)
  workflows/      — сквозные сценарии между ролями (заглушка)
  security/       — тесты на кибератаки, отдельно по каждой роли
    common/       — SQLi в форме логина (рабочий)
    applicant/    — глубокая проверка загружаемых файлов (рабочий)
    expert/       — заглушка, отложено
    admin/        — заглушка, отложено
    predsedatel/  — заглушка, отложено
    sovet_tsuri/  — заглушка, отложено

fixtures/
  applicant/      — синтетические тестовые документы для загрузки
  expert/         — зарезервировано под будущие фикстуры роли
  admin/          — зарезервировано
  predsedatel/    — зарезервировано
  sovet_tsuri/    — зарезервировано

test-files/       — статичный набор QA-подготовленных файлов для security-тестов
                    (не хранится в этом архиве — уже должен быть в репозитории)
```

## Принципы

1. **Page Object Model** — тесты не знают про селекторы, только про методы страниц.
2. **Роли изолированы по папкам** — новая роль или новый общий функционал добавляется без переезда существующей структуры.
3. **Секреты только в `.env`** — не коммитится, шаблон в `.env.example`.
4. **Только синтетические/QA-документы** — реальные медицинские данные пациентов не используются.
5. **Маркеры pytest** — позволяют гонять тесты по роли, исключать security и т.д. без похода по папкам.
