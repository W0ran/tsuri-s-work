# AI Expert — автотесты (Python + Playwright + pytest)

## Стенды

| Окружение     | URL                                          |
|---------------|-----------------------------------------------|
| Тестовый      | https://dev-ai-expert.digitalplatform.kz      |
| Боевой        | https://ai-expert.digitalplatform.kz          |

Тесты по умолчанию работают против тестового стенда (`BASE_URL` в `.env`).

## Карта ролей

| Роль                  | Логин         | Доступ после входа                       | Статус покрытия          |
|-----------------------|---------------|-------------------------------------------|---------------------------|
| Заявитель             | applicant     | `/wizard` (подача заявки)                  | ✅ покрыт                 |
| Эксперт               | expert        | `/expert` (кабинет), `/expert/workflow`, `/expert/{id}`, `/reference` | ✅ покрыт |
| Председатель совета   | predsedatel   | `/council` (специализированная комиссия)   | ✅ покрыт                 |
| Член совета           | sovet_tsuri   | `/council` (та же страница, что и predsedatel) | ✅ покрыт             |
| Администратор         | admin         | всё, включая `/admin`                      | ⏳ UI не изучен            |

Пароли — только в `.env` (не в git, не в этом файле). Роль, для которой в `.env` нет логина/пароля, автоматически пропускается (`pytest.skip`) в тестах, использующих `login_as`.

## Установка

```powershell
pip install -r requirements.txt
python -m playwright install
```

## Запуск тестов

```powershell
python -m pytest tests/ -v --headed
```

Только определённая роль:
```powershell
python -m pytest -m applicant -v
```

Всё, кроме security:
```powershell
python -m pytest -m "not security" -v
```

Быстро, без браузера в видимом режиме (headless, для CI):
```powershell
python -m pytest tests/
```

Полный SQLi sweep полей заявки запускается отдельно: `207` полей x `4` payload'а = `828` кейсов.
Обычный прогон его не включает.

```powershell
# Все payload'ы
python -m pytest -m full_sweep -v --headed

# Быстрый замер на одном payload'е: 207 кейсов
python -m pytest -m full_sweep --sqli-payload "' OR '1'='1" -v --headed

# Один чанк из 15 полей: 15 кейсов с одним payload'ом
python -m pytest -m full_sweep --sqli-payload "' OR '1'='1" --sqli-chunk 1 --sqli-chunk-size 15 -v --headed

# Чанки нумеруются с 1; для 207 полей и размера 15 последний чанк — 14
```

  admin/          — тесты администратора (заглушка)

### ⚠️ Legacy-файлы в корне `pages/` и `tests/`

В репозитории всё ещё лежат файлы, оставшиеся от структуры **до** реструктуризации по ролям
(коммит "Реструктуризация под 5 ролей"): `pages/base_page.py`, `pages/home_page.py`,
`pages/login_page.py`, `pages/upload_page.py`, `pages/wizard_page.py`, а также
`tests/test_login.py`, `tests/test_security_sqli.py`, `tests/test_upload.py`,
`tests/test_upload_large.py`, `tests/test_upload_security.py`.

Их логика полностью продублирована в новой структуре (`tests/common/`, `tests/applicant/`,
`tests/security/common/`, `tests/security/applicant/`), но сами файлы не удалены и
**без маркеров pytest** — поэтому они собираются и выполняются при любом запуске
`pytest tests/`, включая `pytest -m "not security"` (у них просто нет метки `security`,
хотя по сути это security-тесты). Это раздувает список тестов и дублирует покрытие.
Рекомендуется удалить эти 10 файлов после сверки, что новая структура полностью их заменяет.

## Принципы

1. **Page Object Model** — тесты не знают про селекторы, только про методы страниц.
2. **Роли изолированы по папкам** — новая роль или новый общий функционал добавляется без переезда существующей структуры.
3. **Секреты только в `.env`** — не коммитится, шаблон в `.env.example`.
4. **Только синтетические/QA-документы** — реальные медицинские данные пациентов не используются.
5. **Маркеры pytest** — позволяют гонять тесты по роли, исключать security и т.д. без похода по папкам.
6. **Тесты read-only ролей не кликают по необратимым действиям** — например, `predsedatel`/`sovet_tsuri` тесты проверяют доступность кнопок подтверждения/отклонения рассмотрения, но не нажимают их, чтобы не менять статус реальных заявок на общем dev-стенде.
